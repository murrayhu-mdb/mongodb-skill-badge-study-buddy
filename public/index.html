Build Your Own

How this app was made — and how you can make one too, with no coding background.

Everything in this app — the database, the AI-powered search, the website itself — was built by someone with no software engineering background, using an AI coding assistant called Claude Code and MongoDB's own tools for it. If you can describe what you want in plain English, you can build something like this too. Here's exactly how, step by step.

  1. 1

    Pick your topic and content

    Decide what you want your learning hub to teach, and find the source material for it — a set of documents, a website's help pages, an internal wiki, anything text-based and reasonably well-organized. This project used MongoDB's own public documentation, but the same approach works for any subject.

    Tip Aim for 5–20 pages of source material to start. Too little and the AI has nothing meaningful to search; too much makes setup slower and quizzes less focused. You can always add more later.
  2. 2

    Set up a free MongoDB Atlas account

    MongoDB Atlas is where your content lives, along with the AI's ability to search it. Go to cloud.mongodb.com, sign up free, and create an organization and a project — the setup wizard guides you through this. It gives you a free-tier database cluster (called M0) to run everything on, at no cost.

    Tip M0 is perfect for building and testing locally. When you deploy publicly (step 11) you'll need to upgrade to a paid tier — see the note there before spending too long on M0.
  3. 3

    Create a secure service account

    Rather than using your personal login, create a "service account" — a machine identity with its own ID and secret key — so the AI assistant can act on your project without your personal credentials. Grant it just enough permission to manage your one project, not your whole organization — a good habit called least privilege.

    Tip Copy the ID and secret straight into a password manager the moment they're shown — the secret is only revealed once. If you lose it, you have to rotate the account.
  4. 4

    Install Claude Code and MongoDB's plugin

    Claude Code is an AI assistant that writes and runs code for you from plain-English instructions, right in your computer's terminal. Install it, then install MongoDB's official plugin, which teaches it how to directly create databases, search indexes, and queries in your project:

    /plugin install mongodb@claude-plugins-official
/reload-plugins
/mongodb:mongodb-mcp-setup

    That last command walks you through connecting your service account credentials.

    Tip If /plugin install fails with an SSH host key error, use the plugin marketplace's https:// URL instead of SSH. On Mac or Windows you'll also need Node.js installed first.
  5. 5

    Ask it to load your content in

    With everything connected, just describe what you want:

    "Fetch [your source pages] and save each as a clean markdown file in a content folder. Then write a script that reads those files, splits them into overlapping chunks, and loads each chunk into a MongoDB collection. Include the source URL and section heading for each chunk so I can cite them later."

    Claude Code writes and runs the actual code for you.

    Tip Chunk size matters. Ask for chunks of roughly 800–1500 characters with a small overlap between them — big enough for context, small enough for search to be precise.
  6. 6

    Ask it to set up AI-powered search

    "Set up MongoDB Atlas Vector Search on this collection, using automated embedding so I don't have to generate embeddings manually. Also add an Atlas Search (full-text) index on the same field and combine both with $rankFusion for hybrid search."

    Vector search catches meaning (someone can ask a question in their own words); full-text search catches exact keywords. Combining them gives noticeably better answers than either alone.

    Tip Use "Automated Embedding" when creating the vector index — it saves you from running a separate embedding pipeline. Check the region drop-down carefully; not every region supports it on the free tier.
  7. 7

    Ask it to build the backend

    "Build a simple web server with an endpoint that takes a question, searches the content for the most relevant matches, and uses an AI model to answer grounded in those matches. Keep API keys in a .env file."

    You'll need access to an AI model to generate answers — MongoDB employees can use Grove (an internal tool); anyone else can use any OpenAI-compatible provider.

    Tip Always keep secrets (MongoDB connection string, API keys) in a .env file, and add .env to your .gitignore from day one so you never accidentally push credentials to GitHub.
  8. 8

    Ask it to build the website

    "Build a simple webpage with a chat-style interface for asking questions, styled simply and cleanly with a dark theme and a single accent colour."

    Claude Code builds the actual HTML, styling, and interactive behavior.

    Tip Being opinionated about style upfront ("dark theme, MongoDB green accent, generous whitespace") saves you from a generic AI look. You can also save a short style guide file in your project so Claude keeps the same look as you add features.
  9. 9

    Test it and just describe what's wrong

    Click around. If something looks off or you want it to work differently, describe the problem in plain English — "the answers aren't showing the source" or "I want a dropdown of topics instead of free text" — and Claude Code makes the change. This is genuinely how every other feature in this app got built: by describing a need, not by writing code.

    Tip When something breaks, paste the exact error message into Claude Code — the red text from your terminal or the browser console (right-click → Inspect → Console). Vague descriptions get vague fixes.
  10. 10

    Share it temporarily with ngrok

    Once it works locally, share it temporarily with a free tool called ngrok, which gives your locally running app a public web address without needing to formally deploy it anywhere. Great for showing a colleague right now, without committing to a real deployment.

    Tip ngrok URLs change every time by default. Sign up for a free account to keep a stable URL for the length of a demo.
  11. 11

    Deploy it permanently on Render

    For a real, stable public URL, deploy on Render — a free hosting service that pulls your code straight from GitHub. Push your project to a GitHub repository, connect it to Render, and set the same environment variables (MongoDB connection string, API keys) that you used locally.

    Important There are two known issues that will bite you if you don't know about them in advance:
    • Upgrade Atlas from M0 to M10. The free M0 tier intermittently blocks connections from Render's shared IP ranges, which shows up as random "connection refused" errors in production. Upgrading to M10 (a paid Atlas tier) resolves this. This is the single most common reason people give up at the deployment step.
    • Your server must listen on 0.0.0.0 and the PORT Render provides. If it only listens on localhost, Render can't detect it and the deploy fails with "no open ports detected". Ask Claude Code to check both.
    Tip Add a .node-version file at the root of your repo containing your local Node version (find it with node -v). Otherwise Render may default to an older version that doesn't support newer syntax.
  12. 12

    Make it public-safe before sharing widely

    Anyone with your URL can trigger AI calls, which cost money. Two small protections make this much safer:

    • Add rate limiting so a single visitor can't spam the API endpoints.
    • Add basic authentication (a simple username/password prompt) if the app is meant for a specific audience rather than the whole internet.

    Ask Claude Code:

    "Add express-rate-limit to all /api routes at 30 requests per minute, and optional HTTP Basic auth gated by two environment variables."
    Tip Always keep an eye on your AI provider's usage dashboard for the first week after going public. If usage spikes unexpectedly, tighten the rate limit before your bill does.

That's the whole process. Every feature in this app — the guided lessons, the quizzes, the hybrid search, the source citations — was built exactly this way. If you can explain what you want, you can build this.
